# دليل تشغيل ونشر منصة أصولي

> هذا الدليل تقني وتشغيلي. لا يعتمد النصوص القانونية النهائية أو يحل محل مراجعة محامٍ أردني مرخص.

## 1. المتطلبات

تعمل بوابة الملاك في مشروع `ossoolli-portal` باستخدام React/Vite وExpress وtRPC وDrizzle مع قاعدة MySQL/TiDB مُدارة. يلزم Node.js وpnpm واتصال قاعدة البيانات الذي يحقنه المشروع في متغير `DATABASE_URL`.

لا تُحفظ أي مفاتيح أو كلمات مرور داخل GitHub. تعتمد المصادقة على متغيرات البيئة المُدارة في المشروع، ومن ضمنها `JWT_SECRET` وبيانات OAuth وقاعدة البيانات. يجب إدارة أي سر جديد من إعدادات أسرار المشروع، لا من ملفات المصدر أو الالتزامات البرمجية.

## 2. تثبيت الاعتمادات والتشغيل المحلي

نفّذ الأوامر التالية من جذر مشروع البوابة:

```bash
pnpm install
pnpm test
pnpm check
pnpm dev
```

تتحقق الاختبارات من عتبات التصعيد (الأيام 1 و5 و15 و30)، وصلاحيات المستخدم والمشرف، ومنع إنشاء مهمة يومية قبل النشر. لا تستخدم بيانات ملاك أو مستأجرين حقيقية في بيئة التطوير.

## 3. قاعدة البيانات والترحيلات

مصدر الحقيقة لهيكل قاعدة البيانات هو `drizzle/schema.ts`. عند تعديل المخطط:

1. شغّل `pnpm drizzle-kit generate` لتوليد ملف ترحيل SQL.
2. راجع ملف SQL الناتج، لا سيما المفاتيح الخارجية والفهارس والعمليات المؤثرة في البيانات.
3. طبّق الترحيل في قاعدة البيانات المُدارة من خلال قناة الترحيل الخاصة بالمشروع.
4. شغّل `pnpm test` و`pnpm check` بعد التطبيق.

الجداول الأساسية هي: `users` و`owners` و`properties` و`tenants` و`leases` و`payments` و`escalationLogs` و`automationJobs`. لا تُرفع البيانات التشغيلية أو سجلات العملاء إلى GitHub.

## 4. النشر

قبل النشر، تحقق من الآتي:

| الفحص | الحالة المطلوبة |
|---|---|
| `pnpm test` | ناجح |
| `pnpm check` | ناجح |
| ترحيلات قاعدة البيانات | مراجعة ومطبقة |
| مراجعة RTL | سطح مكتب وهاتف |
| GitHub | المصدر والوثائق مرفوعة |
| النصوص القانونية | راجعها محامٍ أردني مرخص قبل إتاحتها للمستخدمين |

احفظ نسخة من المشروع بعد استكمال هذه الفحوص، ثم انشرها من واجهة إدارة المشروع. لا يتم تنفيذ النشر من داخل الكود أو من هذا الدليل.

## 5. تفعيل الفحص اليومي للدفعات

مسار الفحص محمي تحت:

```text
POST /api/scheduled/daily-escalation
```

لا يقبل هذا المسار إلا طلب المهمة الدورية الموثقة من المنصة. بعد **نشر** الإصدار الحالي فقط:

1. سجّل الدخول بحساب المشرف.
2. افتح `/admin` ثم اضغط **«تفعيل فحص يومي»**.
3. تنشئ المنصة مهمة باسم `ossoolli-daily-escalation` تعمل يومياً عند `06:00 UTC`.
4. تُسجل هوية المهمة في جدول `automationJobs`، ولا يُعاد إنشاؤها إن كانت مفعّلة.
5. استخدم **«تشغيل فحص الآن»** للتحقق اليدوي الآمن؛ العملية لا تضيف سجل مرحلة إلا عند انتقال الدفعة إلى مرحلة جديدة.

> وصول الدفعة إلى مرحلة «دعوى إخلاء» هو **إحالة تشغيلية للتدقيق والاعتماد القانوني**، وليس رفع دعوى قضائية تلقائياً أو بديلاً عن قرار محامٍ مختص.

## 6. مسار التصعيد

| التأخر المحسوب | المرحلة | الإجراء التشغيلي |
|---|---|---|
| 1–4 أيام | إشعار ودي | تسجيل تذكير واتخاذ متابعة أولية. |
| 5–14 يوماً | إنذار رسمي | توثيق التأخير وتحويله للمتابعة. |
| 15–29 يوماً | إنذار عدلي | إحالة الملف للتدقيق القانوني وتجهيز مسودة عند الاعتماد. |
| 30 يوماً فأكثر | إحالة إخلاء | إحالة تشغيلية للفريق القانوني؛ لا إجراء قضائي ذاتي. |

## 7. الأمان والخصوصية

لا تشارك بيانات الدخول أو سجلات المستأجرين أو وثائق العقود في المستودع العام. يُمنح كل مالك صلاحية الوصول إلى محفظته فقط، فيما تكون لوحة `/admin` محصورة بحسابات المشرف. احفظ الملفات والعقود مستقبلاً في التخزين الكائني المُدار مع حفظ المرجع والبيانات الوصفية في قاعدة البيانات، لا في مستودع المصدر.
